# Viability-MortaLIVE-Analysis
This is the github repository containing all R-based analyses performed in the "A Multi-Purpose Fluorescent Assay for Quantifying Viability and Morphological Screening in Human Brain Organoids"

## Analyses and manuscript figures

| Figure or task | Notebook section | Enable parameter |
| --- | --- | --- |
| Fig. 1d–e | MortaLIVE compatibility validation: normalized β-III-tubulin and GFAP AUC versus unstained control | `run_validation` |
| Fig. S6 | Bliss independence: observed mixture effect versus expected single-agent combination | `run_bliss` |
| Fig. 3c | MortaLIVE versus immunofluorescence: mean intersection traces and peak radii | `run_comparison` |
| Fig. 3d | MortaLIVE versus immunofluorescence: raw AUC comparisons | `run_comparison` |
| Fig. S7; Fig. 4b–c | Exposure-related Sholl AUC, experiment-specific VC normalization, pooling, and dose comparisons | `run_outgrowth` |
| Fig. 4d | Outgrowth concentration–response fitting and IC50 estimates | `run_ic50` |
| Upstream viability processing | Within-experiment, endpoint- and time-matched VC normalization and workbook combination | `run_viability` |
| Optional preprocessing | Join Fiji Sholl CSV profiles by radius within condition folders | `run_sholl_assembly` |

The workflow starts from quantified fluorescence tables or Sholl intersection profiles. Image segmentation, thresholding, organoid-edge identification, plate assignment, longitudinal ANOVA, resazurin analysis, and viability IC50 fitting are outside its scope. AUC IC50 estimates are exported as tables; a Fig. 4d comparison plot is not generated by the source fitting script or this consolidation.

## Requirements and installation

Use R 4.3 or later and an R Markdown environment. RStudio provides a convenient Knit interface and a bundled Pandoc installation; command-line rendering also requires Pandoc. Install packages once in an R console, outside the notebook:

```r
install.packages(c(
  "rmarkdown", "knitr", "openxlsx", "readxl", "readr", "dplyr", "tidyr",
  "tibble", "purrr", "stringr", "MESS", "ggplot2", "ggpubr", "writexl",
  "janitor", "minpack.lm", "MASS"
))
```

The setup chunk checks packages for enabled analyses and stops if any are missing. It never installs or updates packages during analysis. `sessionInfo.txt` records the actual versions used; this repository does not specify a reconstructed historical package lockfile.

## Quick start

1. Put the notebook at the project root, with input files in a `data` directory or another configured location.
2. Edit the **Configuration** chunk. Replace example paths, sheet names, assay labels, run IDs, and radius settings with the actual inputs. Paths are relative to the notebook directory when rendered normally.
3. Enable the required YAML parameters. All analyses are initially disabled so the methods and code can render without data.
4. Knit the notebook, or run from the project root:

```r
rmarkdown::render(
  "MortaLIVE_analysis.Rmd",
  params = list(
    run_validation = TRUE,
    run_bliss = TRUE,
    run_comparison = TRUE,
    run_outgrowth = TRUE,
    run_ic50 = TRUE
  )
)
```

For a single analysis, enable only its parameter:

```r
rmarkdown::render("MortaLIVE_analysis.Rmd", params = list(run_bliss = TRUE))
```

The outgrowth section runs before IC50 fitting, so both can be enabled in the same render. Otherwise, IC50 inputs must already exist. CSV assembly is a separate preparatory run: inspect and label its output before using it as an analysis input. Use Knit/render for the execution switches to take effect; manually running an individual execution chunk in RStudio bypasses its `eval` switch.

Outputs go to `analysis_output/`. Existing outputs are protected by default. Use a different `output_root` for a new run or explicitly set `overwrite_outputs <- TRUE`. A failed run may leave completed outputs from earlier sections; use a new output directory after correcting inputs, or explicitly allow replacement.

## Input formats

### Viability normalization and combination

Set `viability_files` to a named character vector of workbooks, one per source experiment. Any number of experiments is supported. Names become well-ID prefixes and must be unique.

Matching worksheets use names such as `Cd Norm LD`, `Cr Norm LIVE`, `Cd+Cr Norm DEAD`, and `Pb Norm LD`. Set `analysis_sheet_pattern` if a different naming convention is needed.

| Excel location | Contents |
| --- | --- |
| A1 | Time-column label, e.g. `TIME (h)` |
| Row 1, remaining columns | Treatment name at the first column of each block; subsequent block-header cells blank |
| Row 2 | Well/replicate IDs; unused replicate slots blank |
| Row 3 onward, column A | Numeric time in hours |
| Row 3 onward, remaining columns | Numeric image-derived endpoint measurements; missing observations blank |

Default block order is `VC`, `0.32 µM`, `3.2 µM`, `10 µM`, `50 µM`, `Death Control`. Labels must match `treatment_order` exactly. Blocks must have equal column capacity within an input sheet; capacities can differ between experiments. Preserve the final block's blank capacity in the workbook layout. Well IDs are required for populated columns.

The source workbooks must contain the same set of analysis sheets and the same included timepoints. Time order may differ and is aligned by value. `viability_max_time_h <- NULL` retains all times; set it to `72` to restrict the combined workbook to times at or before 72 h. The individual normalized workbooks retain all source times.

For each sheet and timepoint, every measurement is divided by that experiment's mean VC and multiplied by 100. Missing values are not zeros; a nonpositive or missing VC mean stops normalization. The normalized VC mean is checked against 100 to numerical tolerance. Combination copies the normalized values without averaging or renormalization. Each source Well Map is retained separately when available.

### Bliss independence

Configure one Excel file and sheet. Column names are cleaned to lowercase snake case before validation.

| dose | cd_1 | cd_2 | cr_1 | cr_2 | mix_1 | mix_2 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.32 | numeric %VC | numeric %VC | numeric %VC | numeric %VC | numeric %VC | numeric %VC |
| 3.2 | numeric %VC | numeric %VC | numeric %VC | numeric %VC | numeric %VC | numeric %VC |

Use one row per dose and at least two finite observations per treatment at every dose. Replicate numbers need not match across treatments; bootstrapping is independent. Blank observations are excluded before resampling and counted in the summary. Do not supply ratios on a 0–1 scale: the input is **percentage of VC**.

Single-agent concentrations must match their component concentrations in the mixture. The code cannot determine whether a mixture label denotes each component or total concentration. Confirm that convention before analysis. Fractional effect is `1 - percent_ld / 100`; Bliss excess is `E_mix - (E_cd + E_cr - E_cd * E_cr)`. The default is 5,000 resamples with seed 831 and a 95% percentile interval. Values outside 0–100% generate a warning and remain unchanged.

### Exposure-related outgrowth

`outgrowth_inputs` lists `Assay`, `Run_ID`, `File`, and `Sheet`. Each row contains one independently normalized experiment for one assay. The examples include ML and NO; add GFAP rows for the Fig. S7 analysis. Every sheet to be analyzed must be listed explicitly; sheets are not silently combined.

| Radius | VC_01 | VC_02 | 0.32Cd_01 | 3.2Cr_01 | 10Mix_01 | 10Pb_01 |
| --- | --- | --- | --- | --- | --- | --- |
| numeric distance | intersections | intersections | intersections | intersections | intersections | intersections |

`Ctrl_01` and `Control_01` are accepted as VC aliases. Treatment names use dose followed by `Cd`, `Cr`, `Mix`, or `Pb`, then a replicate suffix. `Cd+Cr` is accepted and standardized to `Mix`. Unsupported names stop the analysis before dose filtering.

`Radius` must already contain the intended edge-relative coordinate. The default expects µm and uses all rows. Set `outgrowth_radius_unit` to the correct label and `outgrowth_radius_step` only if subsampling is intended. Unit labels do not convert the data. To match the older pixel-based acute-metal scripts, use pixel inputs, `outgrowth_radius_unit <- "px"`, `outgrowth_radius_step <- 10`, and `outgrowth_exact <- NULL` for the single-run raw-AUC tests. Pooling retains the normalized Rmd's `exact = FALSE` setting.

Linear trapezoidal AUC is computed separately for each sample and source experiment. Missing intersections are omitted, connecting the remaining points across gaps. Zeroes remain zeroes. No endpoint extrapolation or common radial truncation is added. The output records point counts, missing counts, and integration limits. A profile with fewer than two finite points has missing AUC and an explicit exclusion status. Review unequal integration ranges before interpreting AUC differences.

AUC is normalized to the mean VC within each assay and source experiment. The output is a **ratio with VC mean 1**, not a percentage. Replicates are pooled without averaging source experiments. Unique source/sample identifiers prevent repeated sample suffixes from merging across files. Run identifiers do not establish biological independence; the experimental unit remains a property of the design.

### Compatibility validation — Fig. 1d–e

`validation_inputs` contains `Marker`, `Source_ID`, `File`, and `Sheet`. A workbook has a `Radius` column and sample columns such as `Ctrl_01`, `0.0005ML_01`, and `0.001ML_01`. Control/VC prefixes are recognized; dilution labels can be changed through `validation_groups`.

The source defaults retain radius values at multiples of 10 pixels. If inputs already contain micrometers, set `validation_radius_step <- NULL`, `validation_radius_unit <- "um"`, and leave the scale at 1. For pixel inputs requiring calibration, set a documented `validation_radius_scale` and the corresponding output unit; filtering occurs **before** scaling. The workflow does not assume a microscope calibration.

For each marker, all configured profiles are pooled and AUC is divided by the pooled unstained-control mean, matching scripts 06–07. This is not automatic experiment-specific normalization. Provide only the datasets intended for that comparison.

### Method comparison — Fig. 3c–d

`comparison_inputs` assigns `Method`, `Source_ID`, `File`, and `Sheet` explicitly. Default method labels are `IF_bTubIII`, `IF_GFAP`, and `ML`; column names may be arbitrary unique sample IDs. To reproduce the two-group script, use IF and ML rows only. Alternatively, leave `Method` missing for a combined workbook whose columns contain `_IF_` or `_ML_` tokens.

A combined β-III-tubulin + GFAP group requires its own measured profiles and a manifest row such as `Method = "IF_bTubIII_GFAP"`. It is not reconstructed by summing the separate marker profiles. Repeated replicate suffixes in distinct files remain distinct observations.

Radius subsampling/scaling works as in validation. Defaults preserve the scripts' 10-pixel sampling and pixel units. Set `comparison_radius_step <- NULL` and the correct unit for already calibrated inputs.

Mean profile traces, per-radius n, SD, SEM, pointwise t-based 95% intervals, and all tied maxima of each mean trace are exported. The plotted ribbon is SEM by default; choose `comparison_ribbon <- "CI95_half_width"` to plot the explicitly calculated pointwise 95% intervals. Raw AUC is compared with the configured reference method, ML by default.

### Outgrowth IC50

`ic50_files` is a named vector of pooled CSVs with `Metal`, `Dose_uM`, and `Normalized_AUC`. The outgrowth section creates these files automatically for each assay. `Normalized_AUC` must be a ratio with VC mean 1; the fitting section multiplies it by 100.

The normalized inhibitor-response model fixes Top = 100 and Bottom = 0. The supplied Hill-slope convention uses negative slopes for inhibition. Fits use multiple initial guesses and `nlsLM`, with bounds log10(IC50) = -12 to log10(1000) and HillSlope = -100 to 0. The lowest-RSS converged fit is retained. VC predictions are fixed at 100; VC residuals are still included in fit statistics.

The active confidence-interval method is `confint()` for the nonlinear fit. The unused custom RSS-profile function from the source Rmd is not substituted. Raw interval estimates, reporting-cap columns, boundary flags, convergence failures, and interval status are exported. The source cap is 1,000 µM; a missing interval is labeled unestimated, not asserted to exceed that cap. Extrapolated IC50 values and intervals reaching parameter bounds need interpretation alongside the measured concentration range.

### Optional CSV assembly

Place `*_Sholl-Profiles.csv` files in immediate condition subfolders under `sholl_parent_dir`. Each CSV requires `Radius` and `Inters.`. Files are searched recursively within each condition folder and joined by radius. Duplicate radii or sample IDs stop processing. The output has a `Sholl` sheet and a source manifest. File-derived well IDs still require experimental group assignment before figure analysis; no plate map is inferred.

## Statistical choices to reconcile with figure legends

These settings are intentionally explicit; consolidation does not establish that the manuscript's wording matches the analysis scripts.

| Analysis | Source behavior retained |
| --- | --- |
| Exposure AUC | Two-sided unpaired Wilcoxon tests; BH correction over all dose pairs within each metal; all raw and adjusted p-values exported |
| Normalized outgrowth Rmd | `exact = FALSE`; minimum n = 1 per group for individual runs, 2 for pooled tests |
| Earlier acute-metal scripts | Automatic exact-test choice (`exact = NULL`), 10-pixel sampling, low-n flag below 3; exposed as configuration rather than silently replacing normalized-workflow defaults |
| Fig. 1 normalized AUC | Unpaired `exact = FALSE`, no multiplicity correction |
| Fig. 1 raw GFAP AUC | Lower dilution requests `exact = TRUE`; other raw tests use FALSE; both raw and normalized results are retained separately |
| Fig. 3 AUC | Unpaired `exact = FALSE`, no multiplicity correction, even though organoids may be matched across methods |
| Exposure AUC bars | Mean ± SEM in the supplied scripts; SD is an explicit configuration option |
| Intersection traces | Mean ± SEM in the supplied scripts; a pointwise t-based 95% interval is an explicit option |
| Plot annotation cutoff | Individual-run outgrowth plots display adjusted p < 0.075; pooled plots display adjusted p < 0.05. The display cutoff is not a declaration that p < 0.075 is statistically significant |
| Bliss bootstrap | Independent resampling within treatment and dose, not a paired or experiment-cluster bootstrap |
| Outgrowth pooling | Replicate observations pooled after within-experiment normalization; no experiment-level statistical effect fitted |

The scripts do not implement Bartlett's test. This consolidation does not add it merely because it may be mentioned in manuscript methods. Likewise, it does not convert unpaired tests into paired tests or change SEM to SD automatically. Source code alone cannot identify which differing settings generated a particular final panel. Confirm the intended settings before regenerating publication figures.

Duplicate package loading, repeated helper implementations, hard-coded personal directory structures, conversation-specific comments/citations, duplicate chunk labels, and a nested R chunk delimiter were removed. The normalized-AUC Rmd described a per-well Excel plate formatter but did not implement one; that inactive setting was removed. The supplied CSV assembly utility is included separately.

Implementation corrections are explicit:

- Invalid numeric entries and unrecognized sample labels stop processing rather than silently disappearing.
- Source-file and experiment IDs prevent repeated sample names from merging distinct curves. This can change results where the older scripts inadvertently merged IDs across files.
- Rows without time labels cannot retain populated measurements; normalized worksheet data blocks are cleared before writing to avoid stale rows after blank-row removal.
- Bliss replicate counts use finite observations. Missing values are excluded before bootstrap resampling; this can change intervals for incomplete data. Complete numeric datasets retain the source sampling order, seed, effect formula, and percentile method.
- Unestimable Shapiro tests and insufficient-point profiles return an explicit status instead of crashing or becoming undocumented omissions.
- Nonconverged nonlinear fits are excluded from candidate selection; failed intervals are distinguished from finite or capped intervals.
- Random plot jitter has a fixed seed. Numeric p-value labels replace some source star annotations without changing the tests.
